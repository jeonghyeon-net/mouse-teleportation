# 의존성과 성능 점검

검증일: 2026-10-01 (Asia/Seoul). Apple Silicon, macOS 27.0 (26A428), Release arm64 빌드.

## 의존성

| 범위 | 실제 의존성 | 확인 결과 |
| --- | --- | --- |
| 앱 실행 | Swift 시스템 런타임, AppKit·Foundation·Carbon·CoreGraphics·QuartzCore·ServiceManagement 등 Apple 프레임워크 | 설치된 실행 파일의 `otool -L` 결과가 모두 `/System/Library` 또는 `/usr/lib` 경로 |
| 동적 시스템 연동 | macOS에 포함된 SkyLight | 커서 확대와 활성 디스플레이 전환에만 사용. 비공개 API라는 호환성 제약 있음 |
| Swift 패키지 | 프로젝트 내부 `TeleportCore` | `swift package show-dependencies --format json`의 외부 `dependencies` 배열이 비어 있음 |
| 빌드·검증 | Swift 6+, Python 3.11+ 표준 라이브러리, Make, Git, macOS 빌드·이미지·서명 도구 | pip·npm·Homebrew 패키지를 설치하는 단계 없음. Python은 앱에 포함되지 않음 |
| 릴리스 게시 | 인증된 GitHub CLI | 개발자 머신에서 태그·릴리스와 첨부 파일 게시·검증에만 사용 |
| 선택적 개발 편의 | mise | Make 태스크를 감싼 선택 사항이며 빌드·앱 실행의 필수 의존성 아님 |

앱 번들에는 실행 파일·Info.plist·PkgInfo·아이콘·라이선스·코드 서명만 들어갑니다. README 삽화, Python, Swift 테스트, 개발 도구는 배포 앱에 포함하지 않습니다. 앱 실행 경로에 네트워크 요청, 원격 설정, 자동 업데이트 확인, 분석 SDK가 없습니다.

## 실행 비용을 제한하는 구조

- 평상시에는 OS가 등록된 Option + Tab 이벤트를 전달할 때까지 대기합니다. 포인터 위치·키보드 전체 입력·디스플레이를 주기적으로 검사하는 폴링이나 상시 반복 타이머가 없습니다.
- 화면 목록은 이동할 때만 읽습니다. 짧은 목록을 매번 계산해 모니터 연결 변경에 대응하며 별도 캐시·감시 프로세스를 두지 않습니다.
- 가장자리 효과는 네 개의 Core Animation 그라데이션 레이어를 0.24초 표시합니다. 앱이 매 프레임 전체 화면 이미지를 그리지 않습니다. 이전 효과는 취소하고 종료 후 패널을 닫습니다. 큰 투명 패널의 합성 비용은 존재하므로 “GPU 비용 0”은 아닙니다.
- 커서 확대 중에만 helper 한 개와 약 60Hz 타이머가 실행됩니다. 연속 입력은 실행 중인 helper에 신호를 보내 재사용합니다. 마지막 입력 후 약 0.8초에 원래 크기를 복원하고 종료합니다.
- 별도 helper는 프로세스 시작 비용이 들지만, 본체가 비정상 종료되어도 커서 크기를 복구하기 위한 선택입니다. 1.0.3에서는 helper에 불필요한 `NSApplication` 초기화를 제거했습니다.

## 측정값

본체의 짧은 관찰에서 10.04초 동안 누적 CPU 시간은 0.01초 증가했고, 2초 간격의 `ps` CPU 표시는 모두 0.0%였습니다. RSS는 35.81–35.92MiB였습니다. 이는 1.0.2 본체의 짧은 구간 측정이며 1.0.3 변경은 helper의 시작 경로에 한정됩니다. CPU 표시의 반올림 때문에 “CPU를 전혀 쓰지 않는다”는 뜻은 아닙니다.

helper는 각 빌드를 한 번 실행한 뒤 `/usr/bin/time -l <실행 파일> --cursor-pulse`로 이전·변경 후 빌드를 번갈아 3회씩 측정했습니다. 아래 값은 중앙값입니다.

| 지표 | 변경 전 | 불필요한 NSApplication 초기화 제거 후 |
| --- | ---: | ---: |
| 최대 RSS | 33.19MiB | 10.83MiB |
| 최대 메모리 footprint | 7.94MiB | 3.55MiB |
| 프로세스 전체 경과 시간 | 0.85초 | 0.82초 |
| user + sys CPU 시간 | 0.02초 | 표시 정밀도 0.01초 미만 |

전체 경과 시간에는 의도한 0.8초 확대 효과가 포함되어 있으며 단축키 응답 지연 수치가 아닙니다. 첫 실행 시 변경 후 빌드의 경과 시간은 1.26초로, 반복 실행보다 길었습니다. 위 표는 첫 실행 지연 개선을 증명하지 않습니다. RSS는 공유 메모리를 포함하므로 앱의 독점 메모리나 배터리 소비량과 같지 않습니다.

Instruments를 이용한 장시간 누수 검사, 에너지·GPU 프로파일링, 다양한 화면 해상도와 OS 버전의 성능 비교는 아직 수행하지 않았습니다. 네이티브 구성·상시 작업 제거·실측 개선은 확인했지만 모든 환경에서 최적이라고 단정하지 않습니다.
